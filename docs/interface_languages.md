# Interface translations

The interface picker contains exactly 37 English language names, sorted alphabetically. The existing ten options are retained; the 27 additions come from the spoken-language catalog. Spoken-language selections remain independent matching data.

`app/interface_i18n.py` owns local translations. English source strings are stable lookup keys. `ui(source)` is a reactive frontend lookup against the signed-in or guest preference; `translate(code, source)` is the equivalent Python lookup. Both return the English source only when a translation is absent. Never pass a member name, message, post, review, biography or draft to these lookups.

All 37 choices have core navigation, onboarding welcome and action translations. Extended onboarding and core-screen coverage includes bounded source groups for setup/privacy and the eight-step guided tour across the 36 offered non-English locales plus legacy Hausa. Broader screen coverage remains partial, not represented as full translation: the language pre-screen and Settings explain the English fallback. Explicit offline catalogs now also cover the bounded Settings notifications/date and phone-privacy group (16 exact sources) across all 36 offered non-English locales plus legacy Hausa. These entries preserve the private-location/map-visibility distinction and named date/radius slots; number formatting and the 1–1000 km control bounds remain unchanged. The shared report workflow also has a bounded 42-source offline catalog across these locales, covering its fixed dialog copy, category display labels, whole titles and feedback while preserving member content and canonical values. Add reviewed translations to the catalogs using exact source keys; never substitute unrelated text or prefix English with a language name.

The unnumbered language screen precedes step 1. Its confirmation flag and language are stored in the existing onboarding answers object. Steps remain 1–13, the setup version remains 3, and existing advanced or completed progress rows are not sent back to the language gate. Member preference changes update the existing subscriber preference and merge into onboarding answers in one transaction. Guest preference uses browser local storage and survives refresh and sign-out. Account preference takes precedence at sign-in and session restoration.

The main app disables automatic browser translation. Member-authored content is untouched. Language selection is available on the guest map, guest registration surface, every onboarding screen and member Settings. The native select supports keyboard navigation; the pre-screen focuses its heading and remains independently scrollable on mobile.

Focused language tests: `python -m unittest app.test_interface_languages`. Settings group coverage: `python -m unittest app.test_settings_notifications_translation`. The latest combined 65-test translation suite passed before this bounded continuation; rerun the focused suites after catalog changes. Tests are offline and do not call an external translation service. Coverage is group-specific and does not imply that all app-authored copy is translated.
